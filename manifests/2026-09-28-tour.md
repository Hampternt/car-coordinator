## Goal

A new team leader opening Car Coordinator for the first time sees one notice: **New here? … Show me around**. Pressing it starts a short walk through the setup in the order they would do it: cars, packing spots, drivers, filling a route, warnings, printing, sending the list, where the data lives, and backups. Each step highlights one thing on the page and explains it in a sentence or two. The walk can be reopened at any time from a **Tour** button. The tour only points. It never writes to the plan, the backups or the save file. Its one write is a per-PC key noting that the tour has been seen. A test fails as soon as a later change to the app breaks any step.

## Design

### Files
- **`docs/tour.js`** (new, classic script, immediately before `app.js`).
  - Exposes `window.Tour`: `STEPS`, `start`, `go(i)`, `end`, `place`, `init(hooks)`.
  - The CSP allows a same-origin script (index.html:14), and `check.sh` already syntax-checks `docs/*.js`.
- **`docs/index.html`**:
  - the script tag;
  - `<div id="tourRing" hidden>` and `<div id="tour" class="tour" role="dialog" aria-labelledby="tourTitle" hidden>` after `#tagMenu` (:59), outside `main`, so `render()` never replaces them;
  - the Tour button, placed per the owner's answer.
- **`docs/style.css`**:
  - `.tour` and `#tourRing` rules from `:root` tokens;
  - `[hidden]` rules;
  - `#tourRing { pointer-events: none; }`;
  - `#tour, #tourRing` added to the print rule at :346.
- **`docs/app.js`**:
  - `try { Tour.place() } catch (e) { console.error(e) }` after `renderTagMenu()` at :1106;
  - `if (act === 'tour') { Tour.start(b); return; }` beside :1575-1576;
  - `Tour.init(hooks)` as the first line of `start()`, before the `await` at :2274;
  - a second drain of Store notices, then `offerTour()`, in the offers slot;
  - ids `#planBar` (:703), `#addDriverBar` (:841), `#addCarBar` (:902), `#fileCard` (:1004) and `#backupsCard` (:1024). Each gets a one-line comment pointing at `tour.js`. `smoke.mjs:1894`'s `.card:last-child` still matches.
- **`scripts/tour.mjs`** (new): every tour case. `package.json` gains `test:tour`, and `test` becomes `smoke.mjs && tour.mjs && breadify.mjs`.
- **`scripts/smoke.mjs`**: only the first-open notice counts the offer changes. **`scripts/screens.mjs`**: item 7.

### Storage
- One per-PC key: `carcoord:pref:tour = 'done'`, through pack 1's `Store.pref` / `Store.setPref`.
  - Written when the tour ends (Done, Skip or Escape).
  - Read only by `offerTour()`.
  - Both wrapped in try/catch. A failed write only means the offer returns next time. A failed read means no offer.
- `carcoord:v1` and `carcoord:backups` are never touched.
- The Windows app serves `docs/` from its own origin (tauri.conf.json:7), so it keeps its own key.

### Start-up and the offer
- `Tour.init({ showTab, closeLayers, besideAnchor })` runs first in `start()`.
  - `Store.init` calls `render` before `start()` resumes (store.js:419, 383), so `place()` must already be safe.
  - `start()` runs at app.js:2299, after every app.js keydown listener exists, so the tour's listener runs after them.
  - `closeLayers` = `closePicker`, `closeTagMenu`, plus pack 8's close.
- After the last start-up snapshot (`dailySnapshot`), drain `Store.takeNotices()` again the way `render()` does (app.js:1098).
  - Today the drain at app.js:2281 runs before the snapshots, so a "storage is full" warning (store.js:225) would sit beside the offer.
- `offerTour()` offers only when all of these hold:
  - `firstRun`;
  - `!/^#d=/.test(location.hash)`. It reads the hash itself, because `Share.readHash` clears it later (app.js:2291, share.js:262);
  - `!notices.some(n => n.kind === 'warn')`, which covers an unreadable save (store.js:181);
  - `!Store.file.handle`. A linked file means this PC was used before: permission `'prompt'` makes recovery return null (store.js:429) while the Data tab offers Reconnect;
  - the key is absent.
- The offer is `note('info', …, { act: 'tour', kind: '', id: '', text: 'Show me around' })`. Keep the pushed notice object as `tourOffer`.
- Offer text: "New here? A two-minute tour shows where everything is. The tour only points at things; anything you type on the page is saved as usual. Used Car Coordinator before? Open your save file or an exported copy from the Data tab first."

### The card
- Top to bottom:
  - "3 of 9";
  - `h3#tourTitle`;
  - one or two sentences;
  - a fixed extra line on step 1 ("The tour only points at things. Anything you type while it is open is saved as usual.") and on step 9 ("Open this tour again any time from the Tour button.", naming where it is);
  - buttons Back (disabled on step 1), Next ("Done" on step 9) and Skip tour, carrying `data-tour="back|next|end"` and handled by the tour's own click listener on `#tour`.
- `start(opener)`:
  - remembers the tab and the opener;
  - calls `closeLayers`;
  - removes `tourOffer` by identity;
  - goes to step 1.
- `go(i)`:
  - `showTab(step.tab)`;
  - finds the target;
  - if it is not fully on screen, scrolls it just under the bar (`clearOfBar` logic);
  - calls `place()`;
  - focuses Next.
- `place()`:
  - does nothing unless initialised and open;
  - re-finds the target every time, because `render()` rebuilds every tab (app.js:1102) and also runs unprompted (store.js:309, 362, 373, 383, 419; app.js:1178);
  - measures and positions, and never scrolls or focuses.
- If the user switches tab mid-tour, the target has zero size and the ring hides. The next Back or Next shows the step's tab again.

### Placement
- Width `min(340px, 100vw - 16px)`. Placed with `besideAnchor(rect, w, h, alignRight)` (app.js:2025-2039): below or above the target, clamped to 8px, scrolling inside itself when short of room.
- `alignRight` applies when the step says `align: 'right'`, or when the target's centre is on the right half of the window (the Print button).
- The card's top is clamped to at least the bar's bottom + 8px. `besideAnchor` clamps only its "above" branch (app.js:2036-2037), so without this a target scrolled under the sticky bar would carry the card over the tabs.
- The ring is the target's rectangle + 4px, clipped to the window and to below the bar, except when the target is inside `.topbar` (step 6).
- A missing or zero-size target gives no ring and puts the card under the bar at the right.
- It has to hold at:
  - 1680 wide (rail beside the table, style.css:136);
  - 1280 (the exe's default, tauri.conf.json:15);
  - 1180 and below (rail stacked above, style.css:299-306);
  - 900×600 (the exe's minimum, tauri.conf.json:17-18);
  - 390 (phone; the tab row scrolls, style.css:355).

### Keyboard and focus
- **Escape** ends the tour unless `e.defaultPrevented`, or `#picker`, `#tagMenu` or pack 8's menu is visible, or `$('#shareDlg').open`. Those take Escape first (app.js:2114, 2146, 2155). A native dialog closes on Escape without `preventDefault`.
- **ArrowRight / ArrowLeft** mean Next and Back only while focus is inside `#tour`, so selects, dates, text boxes and the picker grid keep their arrows.
- **Enter and Space** press the focused button natively.
- **No focus trap.**
- **Focus on close** goes back to the opener if it is still in the document. Otherwise it goes to the Tour button, and failing that to the active tab button, each re-found by selector, because `render()` rebuilds Day plan and Data buttons. The offer's button is gone by then.
